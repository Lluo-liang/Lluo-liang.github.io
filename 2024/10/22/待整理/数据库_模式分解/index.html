数据库_模式分解

  • 模式分解（范式转换）
    • 将函数依赖集进行分解，达到范式转换的目的（第一范式转换为第二范式这种）

保持函数依赖

范式之间的转换一般都是通过拆分属性，即模式分解，将具有部分函数依赖和传递依赖的属性分离出来，来达到一步步优化，一般分为以下两种：

1）保持函数依赖分解

对于关系模式，有依赖集F, 若对R进行分解，分解出来的多个关系模式，保持原来的依赖集不变，则为保持函数依赖的分解。另外，注意要消除掉冗余依赖
(如传递依赖)。

实例：设原关系模式R(A,B,C),依赖集F(A>B,B->C,A->C),将其分解。分解为两个关系模式R1(A,B)和R2(B,C),

此时R1中保持依赖A->B,R2保持依赖B->C,说明分解后的R1和R2是保持函数依赖的分解，因为A->C这个函数依赖实际是一个冗余依赖，可以由前两个依赖传递得到，因此不需要管。

👆 上面做的就是消除冗余依赖。

2）保持函数依赖的判断（补充，第 2 点不强求）。

👇 左边是理论，右边是例题。

1、如果F上的每一个函数依赖都在其分解后的某一个关系上成立，则这个分解是保持依赖的(这是一个充分条件)。也即我们课堂上说的简单方法，看函数每个依赖的左右两边属性是否都在同一个分解的模式中。

无损分解

  • 无损分解：分解后的关系模式能够还原出原关系模式，就是无损分解，不能还原就是有损。

考试真题

给定关系模式R<U,F>, U= {A,B,C,D,E}, F={B→A,D→A,A→E,AC→B} ,则R的候选关键字为( )，分解p={R1(ABCE),R2(CD)} （ ）

  • A.CD

  • B.ABD

  • C.ACD

  • D.ADE

  • A.具有无损连接性，且保持函数依赖

  • B.不具有无损连接性，但保持函数依赖

  • C.具有无损连接性，但不保持函数依赖

  • D.不具有无损连接性，也不保持函数依赖

答案：A D

解答：右边没有出现的元素：C D; 同时可以推出全部元素；因此选 A；
R1 - R2: ABE
R2 - R1: D

第二问中：分解为两个关系模式的时候注意一下：

R1 ∩ R2 = C; R1 - R2 = ABE; R2- R1 = D; 判断是否 C 能推出 → ABE 或者 C → D; 看上面的题目是不能的; 因此是 不具有无损连接性；

保持函数依赖下先看一下是否每一个函数依赖都在其分解后的某一个关系上成立 U= {A,B,C,D,E}, F={B→A,D→A,A→E,AC→B}
分解后的 R1(ABCE), R2(CD) ；
看这个式子是不能看出 A → E 是否成立的；需要使用 “通用方法”来进行下一步的判断。这里直接选择 不保持。选择 D。

练习题

第一题

例题：

假设关系模式R(U,F),属性集U={A,B,C),函数依赖集F={A→B,B→C)。若将其分解为 p={R1(U1,F1), R2(U2,F2)) , 其中U1={A,B), U2={A,C}。那么，分解p( )。

  • A.有损连接但保持函数依赖
  • B.既无损连接又保持函数依赖
  • C.有损连接且不保持函数依赖
  • D.无损连接但不保持函数依赖

解答：这一章节中的保持函数依赖讲述的(1 )保持函数依赖分解 是如何进行函数依赖分解；具体的判断这个分解是否是保持函数依赖，需要看第二部分 (2)保持函数依赖的判断 的内容。
前面提及到的 每一个函数依赖都在其分解后的某一个关系上成立 ； 这里做一个解释，题目中的 U = { A, B , C} ；函数依赖集 F= { A → B, B → C};
分解后的 U1={A,B), U2={A,C} 看不出 B → C 的关系是否成立，因此这里需要使用 “通用方法”来进行下一步的判断。
视频中讲述 tip: 考虑到分值取舍的问题和往年考察真题的经验，一般需要使用“通用方法”判断是否保持函数依赖，那么一般答案会是 不保持。【当然这种方式是有逻辑漏洞的】
是否是无损分解看下一章节的说明，这里能够还原 A，B,C ；因此是无损连接。

答案：D

解析：首先，该分解，U1保持了依赖A->B,然而 B->C没有保持，因此针对 B->C 需要用第2点算法来判断：

result=B,result ∩ U1=B,B+=BC,BC ∩ U1=B, result=B ∪ B=B,result 没变，然后，result 再和 U2 交是空，结束了，不保持函数依赖。

注意，这里B+, +的意思是代表由B能够推导出的其他所有属性的集合，这里，B->C,因此B+=BC。
