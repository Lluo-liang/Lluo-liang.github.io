核心代码分析

结合 Spring AI 的 Tool Calling 机制（基于最新 API 设计）

配置类：ToolCallbackProviderConfig

  • 核心作用​​：动态注册所有 McpTool 实现类作为 AI 可调用的工具集。
  • ​​关键机制​​：
    • ​​MethodToolCallbackProvider​​：Spring AI 提供的工具类，自动扫描 @Tool 注解的方法并生成 ToolCallback 实例
    • ​​工具发现​​：通过 applicationContext.getBeansOfType() 收集所有 McpTool 类型的 Bean，确保新工具实现自动纳入 AI 系统
  • ​​设计意图​​：统一管理工具类，避免手动注册每个工具（符合 Spring 的约定优于配置原则）。

工具接口：McpTool

工具实现类：McpDemoService

​​工具方法注解​​：

  • @Tool​​：声明方法为 AI 可调用工具，description 描述功能（模型据此决定是否调用）。
  • @ToolParam​​：定义参数含义，帮助模型理解输入（如 age 需为整数）。
  • 业务逻辑​​：
    • 通过 IDemoService 查询数据库，返回年龄匹配的 Demo 对象列表。
    • 结果转为 JSON 字符串（符合工具调用返回值需字符串化的要求）。
    • 事务控制​​：@Transactional 确保数据库操作原子性。
    • 安全隔离​​：模型仅能通过工具接口访问数据，无法直接操作数据库。

核心代码分析

功能说明：

  • 这里的SpringWebSocketConfigurator 的核心目的是 ​​解决 @ServerEndpoint 类无法直接使用 Spring 依赖注入（如 @Autowired）的问题​​，并扩展握手阶段的定制能力。
  • WsServerEndpoint 类是 ​​WebSocket 服务的核心端点​​，用于处理客户端与服务器之间的实时双向通信。它的作用类似于传统 Web 应用中的 Controller，但专为 WebSocket 协议设计。
    • 主要作用实现双向数据流

结合 Spring WebSocket 和 Spring AI 的核心机制：

WsServerEndpoint：WebSocket 服务端点​**​

​​注解​​：

  • ​​@ServerEndpoint​​：定义 WebSocket 服务端点的访问路径（ws://host:port/ws）。
    • ​configurator​​：解决 @ServerEndpoint 类无法直接使用 Spring 依赖注入的问题（关键设计）。
  • ​​@OnOpen/@OnMessage​​：处理连接建立、消息接收等生命周期事件。

​ChatService：AI 服务与工具注册​​

见上面分析

​​WebSocketConfig：WebSocket 基础配置​​

  • ​​@EnableWebSocket​​：启用 Spring 的 WebSocket 支持。
  • ​​ServerEndpointExporter​​：自动扫描并注册 @ServerEndpoint 注解的类（必需配置）。

​​SpringWebSocketConfigurator：依赖注入解决方案​​

​​关键设计​​：

  • ​​依赖注入​​：重写 getEndpointInstance() 方法，通过 Spring 容器创建端点实例，支持 @Autowired 等注解。
  • ​​握手扩展​​：modifyHandshake() 可获取请求头，用于鉴权或日志记录。

​​协作流程​​

sequenceDiagram
    participant Client as WebSocket客户端
    participant WsServer as WsServerEndpoint
    participant ChatSvc as ChatService
    participant AI as OpenAI模型
    participant Tool as 外部工具

    Client->>WsServer: 连接建立 (ws:///ws)
    WsServer->>Client: 返回"连接建立"
    Client->>WsServer: {"action":"chat", "payload":{"prompt":"查询用户订单"}}
    WsServer->>ChatSvc: 调用askQuestion("查询用户订单")
    ChatSvc->>AI: 发送问题+工具元数据
    AI->>ChatSvc: 返回工具调用指令（如"getUserOrders"）
    ChatSvc->>Tool: 执行工具调用
    Tool->>ChatSvc: 返回订单数据
    ChatSvc->>AI: 整合工具结果
    AI->>ChatSvc: 生成自然语言回复
    ChatSvc->>WsServer: 返回回复文本
    WsServer->>Client: 发送结果

SSE 和 WS 的区别（连接类型和通信模式）

  • SSE 连接通常是通过普通的 HTTP(S) 请求建立的，URL 通常是以 http:// 或 https:// 开头的，不是 ws:// 或 wss://。
特性 SSE (Server-Sent Events) WebSocket
连接类型 单向通信（服务器 -> 客户端） 双向通信（服务器 <-> 客户端）
协议 基于 HTTP/1.1 的持续连接 独立的 WS 协议（基于 HTTP 升级）
建立方式 通过 HTTP 请求建立，服务器发送事件流 通过 HTTP 请求升级连接为 WebSocket 双向通道
关闭方式 服务器关闭或客户端主动关闭 双方任意一方可关闭连接
