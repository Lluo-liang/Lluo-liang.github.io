SpringBoot调用DS——MCP代码分析

mcp-client

mcp-client 代码实现。

展示了 MCP 客户端的核心逻辑，重点在于与大模型（如 DeepSeek）的交互和工具调用的处理。

代码结构解析

1. 控制器层 McpClientController

  • ​​功能​​：
    1. listTools：暴露 /mcpClient/listTools 接口，返回当前注册的所有可用工具
    2. chat：暴露 /mcpClient/chat?prompt=... 接口，处理用户查询并返回模型响应
  • ​​特点​​：
    • 使用 Spring 的 @RestController 自动处理 HTTP 请求/响应
    • 通过 @AllArgsConstructor 实现依赖注入
    • 日志记录用户请求的 prompt

2. 服务层 ChatService

核心实现解析

1. 工具回调系统 (Tool Callbacks)

  • ​​目的​​：将 MCP 服务端能力转化为大模型可调用的工具
  • ​​实现​​：
    • 遍历所有 McpSyncClient（每个客户端代表一个连接的 MCP 服务端）
    • 将每个服务端暴露的功能转换为标准化的工具定义
    • 生成工具描述供大模型理解和使用

2. ChatClient 构建

  • ​​关键组件​​：
    • openAiChatModel：与大模型交互的核心组件（已配置 DeepSeek API）
    • defaultTools()：注册所有可用的工具回调
  • ​​作用​​：创建能够理解并使用注册工具的对话客户端

3. 问题处理流程

  • ​​工作流程​​：
    1. 用户输入 prompt 传递给 ChatClient
    2. 大模型分析 prompt，判断是否需要调用工具
    3. 如需调用工具：
      • 模型返回工具调用请求
      • 执行对应的 ToolCallback
      • 将工具执行结果返回给模型
    4. 模型生成最终响应

与 MCP 协议的关键集成点

  1. ​​McpSyncClient 的作用​​：

    • 表示与单个 MCP 服务端的同步连接
    • 提供：getClientInfo() (客户端信息)、getServerInfo() (服务端信息)
    • 封装了与服务端通信的具体逻辑

  2. ​​工具映射机制​​：

    • SyncMcpToolCallbackProvider 将 MCP 服务端的功能映射为标准化工具
    • 每个工具包含：
      • 唯一名称
      • 功能描述（供大模型理解）
      • 参数定义
      • 执行逻辑（实际调用 MCP 服务端）

  3. ​​大模型集成​​：

    • OpenAiChatModel 是 Spring AI 的组件
    • 通过配置连接到 DeepSeek API
    • 支持工具调用扩展能力

实际工作场景示例

​​用户查询​​：”查询章若楠用户信息”

  1. 请求到达 /mcpClient/chat?prompt=查询章若楠用户信息

  2. ChatService 收到提示词

  3. 大模型分析后识别需要调用”用户查询”工具

  4. 执行对应 ToolCallback：

  5. 大模型将工具返回结果转换为自然语言响应

  6. 最终响应返回给用户：”章若楠，女，25岁，市场部经理…”

设计亮点

  1. ​​抽象与解耦​​：
    • 通过 ToolCallback 抽象具体服务实现
    • 服务端变更不影响客户端核心逻辑
  2. ​​动态工具发现​​：
    • 运行时自动发现并注册可用工具
    • 支持热更新服务能力
  3. ​​日志监控​​：
    • 详细记录客户端/服务端信息
    • 工具注册过程透明可见
  4. ​​标准化扩展​​：
    • 遵循 Spring AI 的工具扩展接口
    • 兼容不同大模型提供者

这个实现展示了 MCP 客户端的核心价值：作为大模型与实际系统间的智能适配层，将业务能力转化为模型可理解、可执行的操作单元。

mcp-server

以下是关键部分的解析：

核心架构设计

  1. ​​层次结构清晰​​：

    • entity (数据实体)
    • mapper (数据访问层)
    • service & service.impl (业务逻辑层)
    • controller (API层) - 虽然没提供，但前面文档表明有HTTP/SSE/WS端点
    • core (核心协议实现)

  2. ​​MCP服务核心接口​​：

    • 所有MCP工具实现的标记接口
    • 定义服务能力的统一抽象

关键组件解析

1. 工具注册机制

  • ​​动态发现​​：扫描所有实现了 McpTool 的Bean
  • ​​自动注册​​：将发现的工具构建为 ToolCallbackProvider
  • ​​服务曝光​​：核心机制是将服务注册为AI可调用的工具

2. 工具实现示例

  • ​​工具注解​​：
    • @Tool：声明工具方法及其描述（供AI理解）
    • @ToolParam：声明参数及其描述
  • ​​事务管理​​：@Transactional 确保数据一致性
  • ​​标准化返回​​：统一返回JSON字符串便于后续处理
  • ​​业务解耦​​：通过接口 IUserService 访问业务逻辑

3. 实体类设计

  • ​​审计字段​​：继承自 BaseEntity
  • ​​ID处理​​：
    • @TableId 标识主键
    • @JsonSerialize 解决Long类型精度丢失问题
  • ​​表映射​​：@TableName 指定对应数据库表

4. 数据访问层

  • ​​MyBatis Plus 集成​​：

    • 继承 BaseMapper 获得基础CRUD能力
    • 继承 ServiceImpl 简化服务实现

  • ​​Lambda 查询​​：

    提供类型安全查询

核心配置解析

1. MyBatis Plus 配置

  • ​​插件链​​：
    1. 分页插件
    2. 乐观锁插件（支持版本控制）
    3. 安全插件（防止全表操作）
  • ​​事务管理​​：@EnableTransactionManagement 开启声明式事务

2. SSE处理过滤器

  • ​​SSE识别​​：通过Accept头识别SSE请求
  • ​​请求日志​​：记录重要请求信息用于调试
  • ​​响应式处理​​：基于WebFlux的响应式编程模型

服务配置

  • ​​服务标识​​：配置唯一服务名称
  • ​​版本管理​​：明确服务版本号

启动类

  • ​​组件扫描​​：@SpringBootApplication 启用自动配置
  • ​​Mapper扫描​​：@MapperScan 定位MyBatis接口

核心设计亮点

  1. ​​插件化工具系统​​：

    • 通过 McpTool 接口实现功能扩展
    • 自动发现机制简化集成

  2. ​​AI友好设计​​：

    • @Tool 和 @ToolParam 提供元数据
    • 自然语言描述帮助AI理解功能

  3. ​​安全与事务​​：

    • SQL注入防护
    • 乐观锁并发控制
    • 声明式事务管理

  4. ​​响应式支持​​：

    • SSE支持实时通知
    • WebFilter进行连接管理

  5. ​​标准化接口​​：

    • 统一返回JSON格式
    • 一致的错误处理机制

工作流程总结

  1. ​​注册阶段​​：

    • 应用启动时收集所有 McpTool 实现
    • 构建工具元数据

  2. ​​AI调用阶段​​：

    • AI选择工具和方法
    • 参数转换后调用服务

  3. ​​业务处理​​：

    • 服务层执行业务逻辑
    • 数据访问层处理DB操作

  4. ​​结果返回​​：

    • 业务对象转为JSON
    • 通过协议(MCP)返回AI

这个设计实现了MCP协议的核心价值：作为AI模型与业务系统之间的智能适配层，通过标准的工具描述使AI能够理解和调用业务能力。
