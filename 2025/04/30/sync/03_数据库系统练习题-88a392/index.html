6.假设系统中有正在运行的事务，若要转储全部数据库，则应采用()方式。

A.静态全局转储
B.动态增量转储
C.静态增量转储
D.动态全局转储

答案：D

解析：正在运行是动态，全部是全局。

记忆技巧

  • 动态 vs 静态：

    • 动态：有活动（事务运行）。

    • 静态：无活动（无事务运行）。

  • 全局 vs 增量：

    • 全局：全部数据。

    • 增量：部分数据。

题目中“有正在运行的事务” → 动态；“全部数据库” → 全局。因此选D。

03

给定关系模式R(U,F),其中U为属性集，F是U上的一组函数依赖，那么函数依赖的公理系统(Armstrong 公理系统)中的分解规则是指( )为F所蕴涵。

  • A.若X→Y,Y→Z,则X→Y
  • B.若Y ⊆ X ⊆ U, 则X→Y
  • C.若X→Y,Z ⊆ Y,则X→Z
  • D.若X→Y,Y→Z,则X→YZ

答案：C

Armstrong公理系统简介

Armstrong公理系统是用于推导函数依赖的逻辑规则，包含以下基本公理：

  1. 自反律（Reflexivity）：若Y ⊆ X ⊆ U，则X → Y。
    • 这是平凡的依赖，因为一个属性集总是决定自己的子集。
  2. 增广律（Augmentation）：若X → Y，则XZ → YZ（Z是任意属性集）。
    • 在函数依赖的两边同时增加相同的属性集。
  3. 传递律（Transitivity）：若X → Y且Y → Z，则X → Z。
    • 类似于数学中的传递性。

此外，还有一些导出规则（可以从基本公理推导出的规则）：

  • 合并规则（Union）：若X → Y且X → Z，则X → YZ。
  • 分解规则（Decomposition）：若X → YZ，则X → Y且X → Z。
    • 这是题目中提到的分解规则。
  • 伪传递规则（Pseudotransitivity）：若X → Y且WY → Z，则WX → Z。

分解规则的定义

分解规则是指：如果已知 X→YZ，则可以推出 X→Y 和 X→Z。

  • 这是因为 Y⊆YZY⊆YZ 和 Z⊆YZZ⊆YZ，所以根据分解规则，可以从 X→YZX→YZ 分解为更小的函数依赖。
  • 形式化描述：若 X→YX→Y 且 Z⊆YZ⊆Y，则 X→ZX→Z。

选项分析

我们需要找到与分解规则形式化描述一致的选项：

  • A. 若X→Y, Y→Z, 则X→Y：

    • 这是传递律的一部分，但不是分解规则。X→Y已经是已知条件，没有分解。
    • 不正确。

  • B. 若Y ⊆ X ⊆ U, 则X→Y：

    • 这是自反律的定义，不是分解规则。
    • 不正确。

  • C. 若X→Y, Z ⊆ Y, 则X→Z：

    • 这正是分解规则的形式化描述：
      • 已知 X→Y，且 Z⊆Y，则可以推出 X→Z。
    • 正确。

  • D. 若X→Y, Y→Z, 则X→YZ：

    • 这是合并规则和传递律的结合，不是分解规则。
    • 不正确。

排除法

  • A：传递律相关，排除。
  • B：自反律，排除。
  • D：合并规则，排除。
  • 只有C完全匹配分解规则的定义。

常见混淆点

  • 可能会误选D，因为D看起来像是“分解”的逆过程（合并）。但分解规则是“从大推到小”，而D是“从小推到大”。
  • 可能会误选B，因为B涉及子集关系，但B是自反律，不是分解。

正确答案是 C. 若X→Y, Z ⊆ Y, 则X→Z。

题目

  1. 给定关系 R (A, B, C, D) 和 S(A, C, E, F)，以下（ ）与 σR.B>S.E(R≈S) 等价。

A. σ2>7(RxS)
B. π₁,₂,₃,₄,₇,₈(σ₁=₅∧₂>₇∧₃=₆(RxS))
C. σ₂>’7’(RxS)
D. π₁,₂,₃,₄,₇,₈(σ₁=₅∧₂>’7’∧₃=₆(RxS))

答案：B

解析：

  1. 原式分析：

    • R≈S 表示自然连接（Natural Join），要求 R.A = S.A 且 R.C = S.C。
    • σR.B>S.E 表示在连接结果中筛选 R.B > S.E 的元组。

  2. 笛卡尔积与条件转换：

    • 自然连接可转换为 笛卡尔积（RxS） 后筛选公共属性相等：
      • R.A = S.A（即第1列 = 第5列）
      • R.C = S.C（即第3列 = 第6列）
    • 再加上 R.B > S.E（即第2列 > 第7列）。

  3. 选项分析：

    • **A. σ₂>₇(RxS)**：
      • 仅筛选第2列 > 第7列，但缺少自然连接条件（R.A = S.A 和 R.C = S.C），不等价。
    • **B. π₁,₂,₃,₄,₇,₈(σ₁=₅∧₂>₇∧₃=₆(RxS))**：
      • σ₁=₅∧₂>₇∧₃=₆ 对应自然连接条件（R.A = S.A，R.C = S.C）和筛选条件（R.B > S.E）。
      • 投影 π₁,₂,₃,₄,₇,₈ 保留 R 的所有属性和 S 的 E、F，消除重复的 A、C，等价。
    • **C. σ₂>’7’(RxS)**：
      • 条件 2>’7’ 将数值与字符串比较，类型错误。
    • **D. π₁,₂,₃,₄,₇,₈(σ₁=₅∧₂>’7’∧₃=₆(RxS)))**：
      • 类似 B，但条件 2>’7’ 存在类型错误。

  4. 结论：

    • 只有 B 正确结合了自然连接条件、筛选条件和投影操作，与原式等价。

某企业开发信息管理系统平台进行E-R图设计，

人力部门定义的是员工实体具有属性：员工号、姓名、性别、出生日期、联系方式和部门，

培训部门定义的培训师实体具有属性：培训师号，姓名和职称，其中职称={初级培训师，中级培训师，高级培训师}，

这种情况属于（1），在合并E-R图时，解决这一冲突的方法是(2)

  • A.属性冲突

  • B.结构冲突

  • C.命名冲突

  • D.实体冲突

  • A.员工实体和培训师实体均保持不变

  • B.保留员工实体、删除培训师实体

  • C.员工实体中加入职称属性，删除培训师实体

  • D将培训师实体所有属性并入员工实体，删除培训师实体

答案： B C

冲突类型分析（问题一）

题目中，人力部门定义的员工实体和培训部门定义的培训师实体存在以下差异：

  • 员工实体属性：员工号、姓名、性别、出生日期、联系方式、部门
  • 培训师实体属性：培训师号、姓名、职称
  • 职称属性有固定取值范围（初级、中级、高级），而员工实体中缺少该属性。

这种冲突属于结构冲突。结构冲突是指同一现实对象在不同应用中抽象为不同的实体或属性集合。例如，员工和培训师本质可能是同一类对象（员工可以兼任培训师），但不同部门根据需求定义了不同的属性（员工实体缺少职称，培训师实体缺少部门等）。因此，答案是 B. 结构冲突

解决方法分析（问题二）

合并E-R图时，需解决结构冲突：

  • 培训师实体的职称是员工实体中缺失的关键属性。
  • 培训师号与员工号可能冲突（如两者均为唯一标识符），但员工号作为主键更合理（培训师本质是员工的一种角色）。

合理做法是将职称属性加入员工实体，删除冗余的培训师实体。这样，合并后的员工实体既能表示普通员工，也能表示培训师（职称可为空或设为默认值）。

  • 选项C（员工实体加入职称属性，删除培训师实体）正确。
  • 选项D（并入所有属性）不合理，因为培训师号与员工号可能重复或冲突，且姓名属性已存在。

通常在设计关系模式时，派生属性不会作为关系中的属性来存储。

按照这个原则，原设计的学生关系模式为Students(学号，姓名，性别，出生日期，年龄，家庭地址)，那么该关系模式正确的设计应为(5)。

  • A,Students(学号，性别，出生日期，年龄，家庭地址)
  • B.Students(学号，姓名，性别，出生日期，年龄)
  • C.Students(学号，姓名，性别，出生日期，家庭地址)
  • D.Students(学号，姓名，出生日期，年龄，家庭地址)

答案：C

解析；

派生属性是指可以由其他属性通过计算来获得，若在系统中存储派生属性，会引起数据冗余，增加额外存储和维护负担，还可能导致数据的不一致性，故派生属性不会作为关系中的属性来存储。

本题中“年龄”是派生属性，该属性可以由“系统当前时间-出生日期”计算获得，故关系模式Students正确的设计是“年龄”不作为关系中的属性来存储。

在分布式数据库中有分片透明、复制透明、位置透明和逻辑透明等基本概念。

其中，(8)是指用户无需知道数据存放的物理位置。

  • A.分片透明
  • B.逻辑透明
  • C.位置透明
  • D.复制透明

解析：

在分布式数据库中，“透明”（Transparency）指的是对用户或应用程序隐藏系统的复杂性。用户不需要了解数据是如何存储、分布或管理的，可以像使用单一数据库一样进行操作。

每个选项的具体含义：

  1. 分片透明（Fragmentation Transparency）：

    • 定义：用户无需知道数据是否被分片（即数据是否被分割成多个部分存储在不同的地方）。
    • 例子：一个表被水平或垂直分片，但用户查询时不需要指定分片信息。

  2. 复制透明（Replication Transparency）：

    • 定义：用户无需知道数据是否被复制（即同一数据是否有多个副本存储在不同的节点上）。
    • 例子：数据可能有多个副本以提高可用性，但用户不需要关心访问的是哪个副本。

  3. 位置透明（Location Transparency）：

    • 定义：用户无需知道数据存放的物理位置（即数据具体存储在哪个节点或站点）。
    • 例子：用户查询数据时，不需要指定数据的物理位置（如服务器名称、IP等）。

  4. 逻辑透明（Logical Transparency）：

    • 定义：这个术语在分布式数据库中并不常见。可能是“视图透明”或“命名透明”的误用。通常指用户看到的逻辑结构与实际物理存储无关。
    • 排除：因为不常见，且其他选项更符合题意。

答案：C 位置透明

分布式数据库系统除了包含集中式数据库系统的模式结构之外，还增加了几个模式级别，

其中(8)定义分布式数据库中数据的整体逻辑结构，使得数据使用方便，如同没有分布一样。

  • A.分片模式
  • B.全局外模式
  • C.分布模式
  • D.全局概念模式

分布式数据库系统通常包含以下模式级别（从高到低）：

  1. 全局外模式（Global External Schema）：

    • 对应于集中式数据库的外模式（视图层）。
    • 是用户或应用程序看到的数据视图，可以屏蔽分布细节。

  2. 全局概念模式（Global Conceptual Schema）：

    • 定义分布式数据库中数据的整体逻辑结构，描述所有数据的逻辑关系。
    • 目标是让用户使用数据时感觉像在使用单一数据库（分布透明性）。

  3. 分片模式（Fragmentation Schema）：

    • 定义数据如何被分片（水平分片、垂直分片或混合分片）。
    • 例如，将表按行或列划分到不同节点。

  4. 分布模式（Distribution Schema）：

    • 定义分片的物理存储位置（即分片分配到哪个站点或节点）。
    • 也称为“分配模式”

答案 D

全局概念模式是定义分布式数据库整体逻辑结构的核心模式级别，确保用户无需感知数据分布。

数据仓库中，数据(8)是指数据一旦进入数据仓库后，将被长期保留并定期加载和刷新，可以进行各种查询操作，但很少对数据进行修改和删除操作。

  • A.面向主题
  • B.集成性
  • C.相对稳定性
  • D.反映历史变化

答案： C

数据仓库4大特点：

  • 面向主题：数据按主题组织。
  • 集成的：消除了源数据中的不一致性，提供整个企业的一致性全局信息。
  • 相对稳定的（非易失的）：主要进行查询操作，只有少量的修改和删除操作（或是不删除）。
  • 反映历史变化（随着时间变化）：记录了企业从过去某一时刻到当前各个阶段的信息，可对发展历程和未来趋势做定量分析和预测。

数据挖掘是从数据库的大量数据中揭示出隐含的、先前未知的并有潜在价值的信息的非平凡过程，主要任务有（)。

  • A.聚类分析、联机分析、信息检索等
  • B.信息检索、聚类分析、分类分析等
  • C.聚类分析、分类分析、关联规则挖掘等
  • D.分类分析、联机分析、关联规则挖掘等

解析；

  • 1、数据挖掘是什么
    • 数据挖掘是从大量数据中揭示隐含、未知且有潜在价值信息的过程
    • 数据挖掘一般是指从大量的数据中通过算法搜索隐藏于其中信息的过程。数据挖掘通常与计算机科学有关，并通过统计、在线分析处理、情报检索、机器学习、专家系统（依靠过去的经验法则）和模式识别等诸多方法来实现上述目标
  • 2、数据挖掘的主要任务
    • 数据挖掘的核心任务聚焦于从数据中发现规律，而非单纯的数据查询（OLAP）或信息查找（信息检索）。
  • 排除
    • A B 包含了信息检索，可以进行排除
    • 联机分析（OLAP）是数据仓库的多维查询技术，属于数据分析工具而非数据挖掘的核心任务；信息检索（如搜索引擎）是独立领域，与数据挖掘目标不同。D 进行排除
    • 答案：C
