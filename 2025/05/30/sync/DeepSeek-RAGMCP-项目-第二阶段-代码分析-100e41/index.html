DeepSeek RAG&MCP 项目-第二阶段-代码分析

Ollama 配置与测试类

配置类分析 (OllamaConfig)

这个类的作用就是执行我需要存储到哪里

核心组件说明

  1. 向量存储类型：

    • SimpleVectorStore：内存存储，适合测试/小规模数据
    • PgVectorStore：基于PostgreSQL的持久化存储，适合生产环境

  2. 嵌入模型配置：

    • 使用nomic-embed-text模型生成文本嵌入
    • 固定768维向量（见SQL注释）

  3. 数据库表结构（SQL注释）：

    • 使用pgvector扩展存储向量
    • JSONB类型存储灵活的元数据

?设计考量

  1. 双存储策略：

    • 开发/测试环境使用内存存储
    • 生产环境使用PostgreSQL存储
    • 通过Bean名称(ollamaSimpleVectorStore/ollamaPgVectorStore)区分

  2. 嵌入模型复用：

    • 两种存储使用相同的嵌入模型配置
    • 确保向量生成一致性

  3. 表名定制：

    • 明确指定表名vector_store_ollama_deepseek
    • 避免自动生成的表名冲突

OpenAI 配置与测试代码分析

配置类分析 (OpenAIConfig)

你注意一下下面两个配置，一个是客户端配置，还有一个是默认工具配置

核心组件说明

  1. 文本分割器 (TokenTextSplitter):

    • 用于将大文本分割成适合处理的块
    • 保持语义连贯性的同时适配模型输入限制

  2. OpenAI API 客户端:

    • 基于配置参数动态创建
    • 支持自定义基础URL（兼容私有部署）
    • 通过API密钥进行认证

  3. 向量存储选项:

    • 内存向量存储 (SimpleVectorStore):
      • 适合开发测试和小规模数据
      • 使用OpenAI嵌入模型生成向量
    • PostgreSQL 向量存储 (PgVectorStore):
      • 生产级持久化存储
      • 指定表名vector_store_openai
      • 使用1536维向量（OpenAI嵌入维度）
      • SQL注释提供了表结构定义

  4. 聊天客户端 (ChatClient):

    • 基于OpenAiChatModel构建
    • 支持工具调用（通过ToolCallbackProvider）
    • 设置默认模型为gpt-4o

数据库表结构设计

  • UUID主键：确保全局唯一标识
  • JSONB元数据：灵活存储文档属性
  • 向量维度：适配OpenAI嵌入模型输出

测试类分析 (OpenAiTest)

测试用例分类

测试类型 方法名 测试重点 使用模型
基础功能 test_call 同步API调用 gpt-4o
多模态 test_call_images 图像理解能力 gpt-4o
流式响应 test_stream 流式输出处理 gpt-4o
知识管理 upload 文档处理流程 -
RAG集成 chat 检索增强生成 gpt-4o

关键技术点

  1. 多模态测试:

    • 使用UserMessage封装文本和图像
    • Media类指定MIME类型和资源
    • 验证GPT-4o的多模态理解能力

  2. 流式响应处理:

    • 使用Flux处理流式响应
    • CountDownLatch同步测试线程
    • 实时记录每个响应块

  3. RAG全流程测试:

    graph LR
A[用户问题] --> B[向量检索]
B --> C[构建提示词]
C --> D[模型生成]
D --> E[返回结果]
    • 元数据过滤：knowledge == '知识库名称v2'
    • 提示词工程：注入检索到的文档内容
    • 空值处理：安全处理null文档结果

  4. 防御性编程:

    • 避免空指针异常
    • 确保无效检索时仍能继续流程
