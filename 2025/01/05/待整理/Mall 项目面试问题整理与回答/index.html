Mall 项目面试问题整理与回答

以下对提供的文本内容进行了结构化与格式化处理，以提升逻辑清晰度和可读性。各问题按模块整理，并辅以技术要点和实现细节。

1. 项目介绍

项目背景

  • 项目名称：智享校园（B2B2C）
  • 目标用户群：面向大学生群体的购物平台
  • 主要服务基础：
    • 快递驿站
    • 校园便利超市
    • 水吧等服务场景
  • 开发架构：
    • 技术栈：Spring Cloud、Vue、uni-app
    • 包括前台商城系统及后台管理系统：
      • 前台商城：商品推荐、搜索、展示，购物车，订单流程，会员中心等。
      • 后台系统：商品管理、订单管理、促销管理、权限管理等模块。
  • 部署技术：
    • SpringBoot、MyBatis、Redis、MongoDB、RabbitMQ、Elasticsearch、MySQL、Nginx 等。

2. 数据库设计

数据库分库与表设计

共分为 5 个数据库，主要覆盖的业务方向如下：

数据库模块 主要数据表
权限管理 后台用户表、后台用户角色表、后台资源表、后台菜单表、后台登录日志表
商品管理 商品信息表、商品审核记录表、SKU 库存表、产品分类表、商品评价表、相册表、商品属性参数表
订单管理 订单表、购物车表、订单商品信息表、退货原因表、订单操作历史记录表、订单设置表
营销管理 优惠券表、优惠券领取和使用记录表、首页推荐专题表、轮播广告表、优惠券与商品关系表
会员管理 会员表、会员收货地址表、会员成长值变化表、会员积分变化表、会员等级表、会员登录记录表

设计思路：

  • 数据库初期基于需求和微服务架构进行拆分。
  • 数据结构参考上一个有问题的项目，进行优化重构。

3. 项目整体技术架构

技术架构特点

  • 基于微服务：
    • 服务间调用：通过 OpenFeign 实现。
    • 服务注册与发现：使用 Nacos。
  • 前后端分离：
    • 静态资源托管在 Nginx。
  • 缓存设计：
    • Redis 用于验证码校验、手机号校验、分布式 Session。
  • 消息队列：
    • 使用 RabbitMQ 实现超时取消订单及解决订单超卖问题。
  • 核心技术：
    • 后端：Spring Boot、Spring Security、MyBatis、MySQL。
    • 前端：Vue.js 和 uni-app。
  • 常用工具：
    • PostMan（接口调试）、JMeter（压力测试等）。

4. 工程结构设计

构建管理

  • 使用 Maven 进行构建：
    • 父工程：pom 文件统一管理依赖，锁定版本，避免版本冲突。
    • 子模块：开发分模块进行。

5. 模块设计详解

5.1 权限管理模块

  • 功能：
    • 角色管理
    • 用户管理
    • 菜单管理
    • 资源列表
  • 技术：
    • 基于 Spring Security 实现：
      • 登录失败/无权限返回结果的自定义。
      • 分布式 Session 结合 JWT。
    • 访问资源时进行权限校验。

授权机制：

  • 用户登录后，将基本信息存入分布式 Session，并返回 JWT Token。
  • Spring Security 完成权限校验，验证用户是否具备访问指定资源的权限。

5.2 商品管理模块

关键词：SPU（标准商品单元）与 SKU（库存单元）

  • SPU：标准的商品描述单位，描述商品的基础信息。
  • SKU：库存单位，具体到物理上不可分割的单元。
  • 例子：
    • 小米 8（SPU）：描述泛化产品。
    • 小米 8 黑色 64G（SKU）：具体化的某个商品。

功能设计

  • 商品基本信息维护（如名称、副标题、品牌等）。
  • 分类管理：主键 ID、等级、排序等常用字段。
  • 属性、参数、规格管理：针对商品的各种类型字段。
  • 折扣维护：支持会员优惠、满减、阶梯价格等。
  • 防重复提交：通过 Redis 保证请求唯一性。

5.3 搜索模块（基于 Elasticsearch）

搜索功能实现

  • 索引初始化：负责 ES 的底层建立。
  • 增删查：
    • 简单查询：通过 SpringData 提供的 ElasticsearchRepository 简化接口。
    • 复杂搜索：自定义综合搜索功能，使用 ElasticsearchRestTemplate 进行操作。

核心功能点

  • 关键词、品牌 ID、商品类型等多条件搜索。
  • 排序规则：
    1. 新到旧
    2. 销量降序
    3. 价格升序/降序
    4. 默认按相关度排序
  • 推荐商品：基于商品名、品牌 ID、类型等字段计算相关商品。

表数据同步 Elasticsearch 数据

  • 实现方式：
    1. Canal 监听 MySQL Binlog。
    2. 将监听的数据库变更通过 MQ 广播到消费者。
    3. 消费者对 ES 中相应数据进行增删改。
  • 数据一致性设计：
    • 使用 RabbitMQ 保证高吞吐分发，避免漏数据。

5.4 订单管理模块

流程设计

用户端主要流程：

  1. 查询订单列表
  2. 添加订单备注
  3. 对不同状态的订单（未付款、待发货等）执行不同操作。

订单超时处理：

  • 以 RabbitMQ 为主进行超时取消：
    1. 死信队列：TTL 到期后触发消息转发。
    2. 配置示例：
      • 两个交换机：订单状态交换机（TTL 队列）和超时处理交换机。
      • 超时消息转发到死信队列后，消费者执行取消订单、解锁库存等操作。
  • Redis 过期监听/分布式事务 Seata 可进一步优化。

5.5 购物车模块

核心功能

  • 用户购物车信息存储在 Redis 和 MySQL 双层：
    • Redis：快速读写，提高性能。
    • MySQL：防止数据丢失。
  • 数据自动过期：
    • Redis 设置过期时间（如 7 天）。
    • 到期时重新从数据库加载并校验。

逻辑细节

  • 计算优惠逻辑：
    • 不同优惠类型：单品促销、满减、阶梯价格等分别独立处理。
    • 优惠卷适配类型：全场通用、指定分类、指定商品。

5.6 防重校验

  • 实现方法：
    • Redis 分布式锁 + Lua 脚本。
    • 防重 Token 存储 Redis，提交请求时校验并删除 Token。
    • 确保原子性，防止重复提交。

5.7 库存锁定设计

实现方式

  • 核心技术：使用 Redisson 实现分布式锁。
  • 具体实现：
    1. 商品 SKU ID 为锁标识。
    2. 对锁定库存操作进行保存，并在失败时回滚。
    3. 使用 Redis 缓存锁定 Stock 数据。

订单编号生成

  • 格式：8 位日期 + 2 位平台号 + 2 位支付方式 + 自增 ID。

5.8 支付成功回调

回调流程

  1. 支付成功确认后更新订单状态。
  2. 解锁库存，完成真实扣减。
  3. 回退优惠券与积分（如订单取消或支付失败）。

6. 综合总结

以上是对项目各业务模块的详细结构与流程的高度提炼与分解。内容涵盖了从数据库设计、核心技术架构，到业务模块实现的全面分析，

并对高级技术点（如分布式锁、搜索引擎同步、延迟消息队列等）做了深入剖析，适用于面试或项目复盘场景使用。
