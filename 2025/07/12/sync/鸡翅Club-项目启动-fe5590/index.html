项目分析

遇到前端项目访问端口没找到的问题

先分析一下前端项目的目录作用（AI 分析）

src 目录（核心代码）​​

  • ​​assets​​
    静态资源文件：
    • base.less / normalize.less：全局 CSS 样式重置或基础样式。
    • favicon.png / favicon.svg / logo.svg：网站图标和 Logo。
  • ​​components​​
    可复用的 Vue/React 组件。
  • ​​constants​​
    常量定义（如 API 地址、固定配置）。
  • ​​ims​​
    （推测）可能与即时通讯（IM）相关的模块，需结合项目实际功能确认。
  • ​​router/index.tsx​​
    路由配置文件，定义页面跳转逻辑。
  • ​​store​​
    状态管理（如 Redux/Vuex/Pinia）：
    • features/user.infoSlice.ts：用户信息的状态切片（Redux Toolkit 风格）。
    • index.ts：状态管理的主入口。
  • ​​utils​​
    工具函数：
    • request.ts：封装 HTTP 请求（如 Axios 实例）。
    • index.ts：其他工具方法（时间格式化、校验等）。
  • ​​views​​
    页面级组件（与路由直接关联的页面）。
  • ​​入口文件​​
    • App.tsx：项目根组件。
    • main.tsx：应用启动入口文件。
    • vite-env.d.ts：Vite 环境变量类型声明（TypeScript）。

​3. 其他文件​​

  • ​​vite-env.d.ts​​
    Vite 项目的环境变量类型定义，增强 TypeScript 支持。
  • ​​main.less​​
    全局 Less 样式文件（可能包含变量或混合宏）。

—​

  • ​​前端框架​​：React（.tsx 文件 + Redux 状态管理）。
  • ​​构建工具​​：Vite（vite-env.d.ts 文件）。
  • ​​样式​​：Less 预处理器（.less 文件）。
  • ​​代码规范​​：ESLint + Husky + Commitizen。

/utils/request.ts 有对前端请求响应的拦截处理

环境变量文件：Vite 默认从项目根目录的 .env 文件中读取环境变量。根据不同环境

Vite 会根据你运行的命令自动加载对应的环境文件：

  • ​​开发环境​​（npm run dev）→ 优先加载 .env.development
  • ​​生产环境​​（npm run build）→ 优先加载 .env.production
  • ​​通用配置​​：无论哪种环境，.env 中的变量都会被加载（但会被环境专用文件覆盖）。

​​优先级​​：
.env.local > .env.[mode] > .env
（例如：.env.development 会覆盖 .env 中的同名变量）
