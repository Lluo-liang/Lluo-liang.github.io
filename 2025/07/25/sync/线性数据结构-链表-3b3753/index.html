线性数据结构-链表

文章主题： 线性数据结构-链表

主要会结合一下Java实现一下相关的代码，同时这里主要是演示。

链表

目前常见的三种链表结构

单向链表

单链表包含具有数据字段的节点以及指向节点行中的下一个节点的“下一个”字段。可以对单链表执行的操作包括插入、删除和遍历。

双向链表

在“双向链表”中，除了下一个节点链接之外，每个节点还包含指向序列中“前一个”节点的第二个链接字段。这两个链接可以称为’forward（’s’）和’backwards’，或’next’和’prev’（’previous’）。

循环链表

在列表的最后一个节点中，链接字段通常包含一个空引用，一个特殊的值用于指示缺少进一步的节点。一个不太常见的约定是让它指向列表的第一个节点。在这种情况下，列表被称为“循环”或“循环链接”；否则，它被称为“开放”或“线性”。它是一个列表，其中最后一个指针指向第一个节点。

把最后一个节点的 next 指回头节点即可

实现一个链表

讲述一下 LinkedList 的大致实现

链表节点

  • 链表的数据结构核心根基就在于节点对象的使用，并在节点对象中关联当前节点的上一个和下一个节点。通过这样的方式构建出链表结构。
  • 但也因为在链表上添加每个元素的时候，都需要创建新的 Node 节点，所以这也是一部分耗时的操作

头插节点

  • 头插的操作流程，先把头节点记录下来。之后创建一个新的节点，新的节点构造函数的头节点入参为null，通过这样的方式构建出一个新的头节点。
  • 原来的头结点，设置 f.prev 连接到新的头节点，这样的就可以完成头插的操作了。另外如果原来就没有头节点，头节点设置为新的节点即可。最后记录当前链表中节点的数量，也就是你使用 LinkedList 获取 size 时候就是从这个值获取的。

尾插节点

  • 尾差节点与头插节点正好相反，通过记录当前的结尾节点，创建新的节点，并把当前的结尾节点，通过 l.next 关联到新创建的节点上。同时记录 size 节点数量值。

拆链操作

  • unlink 是一种拆链操作，只要你给定一个元素，它就可以把当前这个元素的上一个节点和一个节点进行相连，之后把自己拆除。
  • 这个方法常用于 remove 移除元素操作，因为整个操作过程不需要遍历，拆除元素后也不需要复制新的空间，所以时间复杂读为 O(1)

删除操作

  • 删除元素的过程需要 for 循环判断比删除元素的值，找到对应的元素，进行删除。
  • 循环比对的过程是一个 O(n) 的操作，删除的过程是一个 O(1) 的操作。所以如果这个链表较大，删除的元素又都是贴近结尾，那么这个循环比对的过程也是比较耗时的。

描述一下“链表”这一数据结构

链表是由若干“节点”顺序串联而成的线性表。每个节点包含两部分：

  • 数据域（data）
  • 指针域（next/prev）
    • 节点在内存中非连续，靠指针把逻辑顺序串起来。

根据指针数量与结构不同，衍生出单向、双向、循环三种常见形态。

Java 标准库中的 LinkedList 用的是什么链表结构？

JDK 的 LinkedList 是 双向链表（Doubly Linked List）

什么时候更适合用链表

  • 频繁在 头部/中间 插入/删除，且基本不随机按索引访问
  • 数据量未知，需要动态扩容，又不想像 ArrayList 那样产生大量数组拷贝
  • 实现队列、双端队列、LRU 缓存（LinkedHashMap 内部就是双向链表+HashMap）
    反例：需要大量随机访问、CPU Cache 友好性要求高 → 用数组或 ArrayList 更合适。

实际的一个使用场景

高性能任务重试队列（常见于分布式消息队列、RPC 框架、爬虫调度器）

业务诉求

  1. 任务在头部频繁出队（消费成功）。
  2. 消费失败时需要在任意位置（根据重试策略：指数退避、优先级、延迟时间）把任务重新插入队列。
  3. 任务数量无法预估，高峰期可能瞬间暴涨，需要 O(1) 的动态扩容/缩容。
  4. 不要求按索引随机查看第 n 个任务。
  5. 需要额外支持：
    • 在 1 ms 内把某个任务从队列中删除（取消/超时）。
    • 支持重复任务去重（用 HashMap 记录任务 ID → 链表节点指针）。

技术选型

  • 双向链表（Java LinkedList 或自实现）
    • 头插/头删 O(1) 满足“消费出队”。
    • 已知节点指针即可 O(1) 删除或插入到任意位置，满足“重试插队”。
    • 无需像 ArrayList 那样触发数组拷贝，内存增长平滑。
  • **HashMap<TaskId, Node< Task >> 提供 O(1) 的节点定位，从而支持“删除指定任务”与“去重”。

简单代码骨架

为什么不用 ArrayList？

  • 按“延迟时间”插入时需要遍历 + 数组搬移，最坏 O(n)。
  • 删除指定任务时同样需要 O(n) 查找索引，再 O(n) 搬移。

为什么不用优先队列（堆）？

  • 堆只能把元素放到末尾再 sift-up，无法 O(1) 删除指定节点（除非再维护一张 map → 斐波那契堆，实现复杂）。
  • 双向链表 + HashMap 的组合既简单又满足全部时间复杂度要求。

其他不错的使用场景

# 场景 & 典型业务 为什么“链表”最合适（一句话技术要点）
1 音乐播放器播放列表（网易云/QQ 音乐） 双向链表天然支持“上一首 / 下一首”O(1) 跳转，同时可拖拽任意歌曲到任意位置插队。
2 浏览器前进 / 后退栈（Chrome、Edge） 双向链表 + 当前指针即可 O(1) 完成后退/前进；若用两个栈实现，需要额外搬运。
3 Redis / Netty 的“对象池” 循环链表做空闲对象池，O(1) 借还对象，无锁弹出头节点即可复用。
4 滑动窗口日志 / 时间轮定时器（Kafka、Netty HashedWheelTimer） 把每个时间槽做成链表，定时任务按延迟挂到对应槽，O(1) 插入/取消。
5 Undo/Redo 操作历史（VS Code、Photoshop） 双向链表保存操作快照，支持无限级撤销/重做；若数组实现，删除中间历史时会触发大量搬移。
